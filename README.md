# 《圣经》文体翻译器

保留任意现代中文文案的情节或信息主干，把它重新写成故意庄严过度、略显生硬的《圣经》和合本翻译腔。

输入可以是故事、对白、独白、通知、观点、广告、说明、教程、技术报错、清单、聊天记录或一句短话。系统先识别文本形态，再转换语体；不会把所有内容都强写成一个人物故事。

> 这是文学戏仿工具。输出不是《圣经》经文、经文翻译或宗教权威文本。

## 原文成章

- 保留原文的文本形态与交际目的：通知仍是通知，观点仍在论证，清单仍按顺序列举，短句不会凭空扩成剧情。
- 定义、百科知识和客观事实使用独立的和合本式说明骨架，不进入格言系统；“以甲为乙”等定义关系和被定义名称会被保留，不会凭空变成“有福、有祸”或行为报应。
- 格言只在原文确有行为、品格、选择与后果时触发。选中的语料骨架会直接参与正文，不再把两百多条格言压缩成少数“有福了，因为他必……”格式。
- 保留人物与阵营、核心诉求、专名、现代物品、数字、单位、日期、时辰、关键条件、关键动作归属、伤害对象、胜负关系和结局。
- 有对白时保留说话人、受话人和每段有实质意义的话语功能；寒暄也会映射到迎接、等候、请人坐席等固定句式。原台词不直接作为正文返回。
- 原文成章不再让模型自由写作。模型只输出人物、动作、对象、条件、结果和对白功能的严格 JSON；服务器根据功能选择固定高保留骨架，再把元素机械填入。
- 通过旧译连接、重复主语、条件后果、反问递进、郑重归属和语义扩张制造鲜明的和合本感觉；可适量加入“乃、故、遂、既、惟、其、亦、当、不可”等古拙词，但不写成纯文言。
- 100—200字的短故事先完整保留人物、目的、物品、赠与或借贷方向与结局，再安排一处最合适、可一眼认出的换骨名句；只有原文确实存在第二个独立因果时才加入第二处。允许补入少量不改变因果的场面过渡。避免“说时迟那时快、名不虚传、不动声色、拍案而起”等章回小说或武侠套语。
- 每段直接引语都由服务器绑定完整的高保留名句骨架；只出现“若、必、不可、今日、未曾”等零散旧译词不算。模型不能自创骨架，也不能把普通文言对白混入引号。
- 说话标签按连续上下文生成：一场对话首次才写“甲对乙说”，轮替时缩成“甲回答说／乙说”，同一人物连续发言合并在一个引语标签下；叙事已经点明说话人时直接接“说／大声说”，不重复姓名。“开口说”不再作为普通发言的默认标签。
- 槽位还会按功能二次清洗：删除模型误带入的“若、必、不可、你今日、我当怎样”等骨架词，校正介绍人数与单复数，并阻止“你若有以后若有、凡凡、呢呢、刺伤某人后又说某人受伤”一类重复拼接。
- 单一结果型的技术记事或出行记录可以补一层和合本式收束，如“这事就这样成了”或“这事的结局，就是这样”；已经有明确结局的多段故事不再机械追加尾注。尚未发生结果的威胁、问题或计划不会被伪写成已经完成。
- 允许添加雅间、站位、拍案、拔刀来源、倒地或离开姿态等不改变情节主干的场面润色，但不得反转人物关系、新增关键攻击、改变伤害对象、胜负或结局。
- 现代术语、品牌、产品功能、代码、版本、价格和具体时辰原样保留，庄严句法与现代事物的时代错位就是节目效果。
- 不添加圣经人物、神迹、教义、作者点评、神学教训或输入没有的后续。
- 正向结果按语义自动分节，网页以圣经式上标节号显示；复制正文和导出图片也会保留连续节号，但不会伪造真实书名、章节或经文出处。

系统会在内部区分叙事、独白、通知、观点、广告、技术说明、清单和聊天等形态，并选择相应的旧译句法。只有原文本来是故事时才使用连续记事；清单可以保留列项，通知可以保留公告形式，一句话也可以只输出一句。

强标签按语义使用：“晓谕”只用于有权发布的通知或命令，“起誓、作保”只用于保证承诺，“咒诅”只用于恶言或强烈抱怨。普通报错、失败、不同意和轻微不满不会自动被写成咒诅、刑罚或灭亡。

跨形态示意：

- “我今天真的不想上班，只想在家躺一天”可改成“到了今日，我的心甚是疲乏，不肯往那作工之处去；我所愿的，乃是在家中躺卧一日，好使身心得着安息。”
- “会议改到下午三点，请大家准时参加”可改成“论到这会议，所定的时辰已经更改，乃在下午三点；你们各人当按时聚集，不可迟延，免得错过那所定的时候。”
- “升级到2.1版本后重启服务，否则配置不会生效”可改成“你们既将系统升到2.1版本，就当使服务重新启动；若不如此行，所更改的配置便不能生效，其功用也不得显明。”

示例只规定变形力度，不规定固定人物或词汇；模型必须根据当前输入另造相应的庄严错位。

## 和合本叙事工具箱

项目从公开和合本语料中按功能整理表达方式。生成时只选择当前语义真正支持的结构，不再设置机械的词语或类别数量指标。

完整的原文抽样、文类分析、高辨识度句式锚点和转换算子，见 [`references/CUV_STYLE_ANALYSIS.md`](references/CUV_STYLE_ANALYSIS.md)。

用于离线抽取骨架的完整语料来自 eBible.org 的[新标点和合本（简体）](https://ebible.org/Scriptures/details.php?id=cmn-cu89s)，该来源标记为 Public Domain。仓库内语料说明见 [`references/cuv-corpus/README.md`](references/cuv-corpus/README.md)。

| 功能 | 常见结构 | 可用于现代输入 |
| --- | --- | --- |
| 人物与时间 | 有一个人、名叫、那时、这事以后、及至、到了时候、日期满了 | 人物登场、时间线、截止日期 |
| 观察与突转 | 举目观看、看哪、不料、话还没有说完、听见这话就 | 发现问题、剧情反转、突然来信 |
| 对话与审问 | 回答说、开口说、复问、是甚么缘故、岂不、何等 | 问答、质疑、争论、追责 |
| 命令与承诺 | 晓谕、吩咐、起誓、立约、作保、凭据、追讨 | 通知、保证、合同、承诺 |
| 金钱与交付 | 金银、银子、价银、交在手里、从他手中、归回原主 | 报价、支付、退款、转交 |
| 条件与后果 | 若……就、凡……必、无论……都、好叫、免得、以致 | 规则、条件、风险、结果 |
| 情绪与裁断 | 咒诅、有祸了、刑罚、怒气填胸、变了脸色、看为恶 | 抱怨、冲突、处罚、否定评价 |
| 完成与应验 | 事就这样成了、照样行、必然应验、一句都不落空 | 执行、交付、兑现、验证 |
| 解释与收束 | 原来、因此、故此、起名、直到今日 | 原因、由来、命名、长期后果 |
| 行程与差遣 | 起来往……去、到了那里、从那里出来、回本地去、打发人去 | 出发、出差、配送、离场 |
| 内心与身体 | 心里说、心里想、自言自语、俯伏在地、撕裂衣服、甚惧怕 | 犹豫、盘算、震惊、崩溃 |
| 群众与报信 | 众人听见、合城呼喊、有人告诉、回来报信、并没有隐瞒 | 群聊、转发、汇报、围观 |
| 请求与许可 | 我若在你眼前蒙恩、求你容我、愿你、请指示 | 请假、申请、协商、求助 |
| 尊荣与羞辱 | 蒙恩、看为美、看为恶、尊重、藐视、在众人眼前 | 表扬、拒绝、公开评价、地位 |
| 谱系与行政 | 后代记在下面、数点、按家室宗族、照着数目、各归本家 | 版本沿革、组织图、名单、库存 |
| 反转与智慧 | 本来……如今、反倒、宁可……不愿、尚且……何况、智慧人……愚昧人 | 打脸、递进、观点、经验总结 |
| 呼告与比较 | 我的心哪、为何、何其、何等、如同、好像 | 情绪表达、赞叹、比喻、吐槽 |
| 隐藏与显明 | 隐藏、显明、详细察看、搜出、果然是真的 | 秘密、证据、排查、调试、揭穿 |

这些结构不能机械堆叠。例如没有交易就不写金银，没有旁观者就不写合城呼喊，没有长期结果就不加“直到今日”。

## 输入示例

```text
通知：明天下午三点开项目会，请大家带上最新方案，提前十分钟到会议室。
```

目标输出会保留通知形态、时间、参会要求和提前十分钟到场的条件，同时使用“所定的时辰、你们要、不可迟延”等庄严翻译腔。

## 其他能力

- 把圣经翻译腔反向释义成自然现代中文。

## 本地运行

要求 Node.js 20 或更高版本。

```bash
pnpm install
pnpm dev
```

打开 <http://127.0.0.1:3000>，点击右上角"配置 API"，填入自己的 DeepSeek API Key。

需要按生产环境检查交互时，运行：

```bash
pnpm build
pnpm start
```

Key 保存在 `localStorage`（Web 版）或 `Neutralino.storage`（桌面版）中：

```text
bible-style-deepseek-api-key
```

浏览器只在调用 `/api/translate`（Web 版）时通过 `Authorization: Bearer <用户Key>` 临时发送它。桌面版直接通过 `Neutralino.net.post()` 发送到 DeepSeek API。服务端不读取公共 `DEEPSEEK_API_KEY`，也不持久化用户 Key。

## 桌面版（Neutralinojs）

桌面版使用 Neutralinojs 替代 Electron，将 SPA 打包为原生窗口应用（使用系统原生 WebView2 / WebKit，不捆绑 Chromium）。页面、样式、图片均为本地提供；联网只用于调用 DeepSeek API。

### 架构

```
WebView
  └── resources/index.html（Next.js 静态导出 SPA）
       ├── UI: React
       ├── 业务逻辑: lib/*.ts（纯 TS，前端 bundle）
       └── AI 调用: Neutralino.net.post() → DeepSeek
            （C++ 框架层 HTTP，无 CORS 限制）
```

无本地服务器、无 Node.js 运行时。

### 运行

```bash
pnpm desktop:build   # 构建静态 SPA + 准备 Neutralinojs 资源
pnpm desktop:run     # 构建并启动桌面应用
pnpm desktop:dist    # 构建并打包为分发包
```

### BYOK

桌面版同样采用 BYOK。首次打开后点击"配置 API"，填写 API Key。Key 通过 `Neutralino.storage` 持久化到应用数据目录（`.storage/`），重启不丢失。

## 可选环境变量

```env
AI_BASE_URL=https://api.deepseek.com
AI_MODEL=deepseek-v4-flash
AI_MODEL_CANDIDATES=deepseek-v4-flash,deepseek-v4-pro

# 旧版变量仍兼容
DEEPSEEK_BASE_URL=https://api.deepseek.com
DEEPSEEK_MODEL=deepseek-v4-flash
DEEPSEEK_REVIEW_MODEL=deepseek-v4-flash
DEEPSEEK_MODEL_CANDIDATES=deepseek-v4-flash,deepseek-v4-pro
MAX_OUTPUT_TOKENS=4096
TRANSLATE_TIME_BUDGET_MS=45000
DEEPSEEK_CALL_TIMEOUT_MS=22000
```

Web 部署时在服务端设置；桌面版固定使用 DeepSeek 官方 API，环境变量由用户在前端界面中直接配置。

## 请求流程

1. 浏览器（Web 版）或本地存储（桌面版）读取用户自己的 Key。
2. 浏览器提交正文、翻译方向、文风档位、篇幅和匿名客户端 ID。
3. Web 版由服务端验证输入和频率限制；桌面版由前端管线验证输入。
4. 模型只识别事实元素、叙事顺序和对白功能，返回严格 JSON，不生成正文，也不选择经文句子。
5. 系统按对白功能选择固定名句骨架，把人物、动作、对象、条件和结果机械填槽。
6. 系统用固定叙事框架连接各单元，并执行确定性的场景词替换后立即返回。
7. JSON 无效或关键事实未通过时最多重试识别一次；长故事会保留事实安全的最佳版本，只有借贷方向、伤害对象、否定关系和结局等硬错误仍未修正时才进入紧急版本。

模型请求层兼容主流 OpenAI 格式接口：模型名不支持时优先读取接口返回的可用模型，JSON mode、system role、`max_tokens`、`temperature` 与推理开关不兼容时会自动调整并缓存成功能力。DeepSeek 与 Qwen 兼容接口会优先关闭不必要的长推理，以减少长故事超时。认证、模型配置和参数兼容错误会直接反馈给用户，不会被包装成固定兜底结果。

正向与反向输入上限均为 3000 字。
